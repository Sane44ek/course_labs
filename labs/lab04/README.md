Данная лабораторная работа посвещена практическому анализу и определению мер снижения рисков ИБ. То есть вам, при развитии компетенций в ИБ, будет требоваться доносить требования ИБ, необходимость их выполнения, критичность и важность до коллег. 

Аналогичным образом, с помощью данного практического задания будет понятно на сколько плотно вы взаимодействовали с ИБ, что знаете из основ по обеспечению защиты информации, а также с какими подобными кейсами вы сталкивались в своей практике.

Вы получите навыки оценки задачи в роли специалиста ИБ, посмотрите на кейсы со стороны ИБ и сможете дать свою оценку, как бы вы подошли к этим вопросам в данной ситуации.

## Вводные

Компания зарегистрирована в Евросоюзе и должна соответствовать законодательству ЕС. Работая в данной компании занимаетесь обеспечением ИБ. 

Вы обнаруживаете админскую консоль веб-сайта своей компании, которая доступна неограниченному кругу лиц в сети Интернет, так как публикация торчит во внешний сегмент сети
> - С помощью её интерфейса доступны на просмотр записи с запросами о приобретении продукции компании, которые содержат персональные данные, а также коммерческие предложения (что, в каком объёме, за сколько, специальный условия и т.д.). 
> - Аналогично доступны логи, в которых видны ip-адреса администраторов, которые попадали в нее.

# 🔍 Lab04 — Аналитическая записка по рискам ИБ  
**Статус:** КОНФИДЕНЦИАЛЬНО  
**Распространение:** Только для внутреннего использования  
**Срок актуальности:** 30 дней  

---

## 🔍 Краткое резюме для руководства (Executive Summary)

Обнаружена **критическая уязвимость**:  
Административная панель веб-сайта компании, содержащая **персональные данные клиентов и коммерческую тайну**, доступна из сети Интернет **без аутентификации**.

### Бизнес-риски
- 💰 Штрафы по **GDPR** до **20 млн €** или **4% годового оборота**
- 📉 Потеря конкурентного преимущества из-за утечки коммерческой тайны
- 🧯 Репутационный ущерб и потеря доверия клиентов
- ⚠️ Прямые финансовые потери (мошенничество, шантаж)

### Требуемые действия
**Немедленная блокировка доступа (в течение 24 часов)** и внедрение многоуровневой защиты.

## 🛡️ Предлагаемые меры защиты

### Срочные меры (0–24 часа)

```bash
# Экстренная блокировка через firewall
iptables -A INPUT -p tcp --dport 8080 -s 192.168.1.0/24 -j ACCEPT
iptables -A INPUT -p tcp --dport 8080 -j DROP
# .htaccess (Apache)
Order deny,allow
Deny from all
Allow from 10.0.0.0/8
```
Технические действия:

- Немедленная блокировка публичного доступа

- Временный доступ только с корпоративных IP

- Уведомление руководства об инциденте
#### Краткосрочные меры (1–7 дней)
1. Аутентификация

- MFA (Google Authenticator / TOTP)

- Политика паролей (12+ символов)

- Таймаут сессий — 15 минут

2. Защита канала связи
```bash
server {
    listen 443 ssl http2;
    server_name admin.company.com;

    ssl_protocols TLSv1.2 TLSv1.3;

    location /admin {
        auth_basic "Administrator Area";
        auth_basic_user_file /etc/nginx/.htpasswd;
        allow 10.0.0.0/8;
        deny all;
    }
}

```
#### Среднесрочные меры (2–4 недели)
Архитектурные изменения

```bash
Текущая архитектура:
[Internet] → [Public IP] → [Admin + Frontend]

Целевая архитектура:
[Internet] → [Frontend] → [Backend]
                     ↑
               [VPN / Bastion]
                     ↑
                  [Admin]
```
Реализация:

- VPN (WireGuard / OpenVPN)

- Bastion-host

- Private subnet для админки

- DevSecOps pipeline

- SIEM и централизованный аудит

- Регулярные пентесты

- Обучение персонала ИБ
### 📋 План внедрения мер
#### Фаза 1 — Реагирование (День 1)
Собрать инцидентную группу
Заблокировать публичный доступ
Начать сбор доказательств
Оценить потенциальный ущерб
#### Фаза 2 — Стабилизация (Неделя 1)
Внедрить базовую аутентификацию
Настроить VPN доступ для администраторов
Обновить политики доступа
Провести анализ root-cause
#### Фаза 3 — Укрепление (Месяц 1)
Редизайн сетевой архитектуры
Внедрение RBAC и MFA
Настройка мониторинга и алертинга
Обновление документации
#### Фаза 4 — Оптимизация (Квартал 1)
Автоматизация проверок безопасности
Регулярные тренировки ИБ-инцидентов
Сертификация по ISO 27001/GDPR
Непрерывное обучение сотрудников

### 🧑‍💻 Технические детали реализации
#### 1. Конфигурация безопасной админ-панели
```bash
# Docker Compose пример изолированной админки
version: '3.8'
services:
  admin-panel:
    image: our-company/admin-panel:secure
    networks:
      - internal-admin-net
    ports:
      - "127.0.0.1:8080:8080"  # Только локальный доступ
    environment:
      - AUTH_TYPE=oidc
      - MFA_REQUIRED=true
      - SESSION_TIMEOUT=900
    volumes:
      - ./audit-logs:/var/log/audit

  vpn-gateway:
    image: wireguard/wireguard
    networks:
      - internal-admin-net
      - vpn-net
    cap_add:
      - NET_ADMIN
    ports:
      - "51820:51820/udp"
    volumes:
      - ./wg-config:/config

networks:
  internal-admin-net:
    internal: true  # Изолированная сеть
  vpn-net:
    driver: bridge

```
#### 2. Мониторинг и аудит
```bash
# Пример скрипта мониторинга доступа
import logging
from datetime import datetime

def check_admin_access(log_file):
    """Мониторинг подозрительной активности в админке"""
    alerts = []
    
    with open(log_file, 'r') as f:
        for line in f:
            if '/admin' in line:
                ip = extract_ip(line)
                user_agent = extract_ua(line)
                
                # Проверка на аномалии
                if is_suspicious_ip(ip):
                    alert = {
                        'timestamp': datetime.now(),
                        'event': 'SUSPICIOUS_ADMIN_ACCESS',
                        'ip': ip,
                        'user_agent': user_agent,
                        'risk_level': 'HIGH'
                    }
                    alerts.append(alert)
                    send_alert_to_siem(alert)
    
    return alerts

```
Принимает путь к лог-файлу как аргумент
Возвращает список обнаруженных инцидентов
Открывает файл в режиме чтения
Использует контекстный менеджер (with) для автоматического закрытия файла
Фильтрует строки логов, содержащие путь /admin (стандартный путь к административной панели)
Это базовый метод обнаружения — на практике пути могут быть сложнее
Использует вспомогательные функции для парсинга:
extract_ip() — извлекает IP-адрес из строки лога
extract_ua() — извлекает User-Agent (информацию о браузере/устройстве)
